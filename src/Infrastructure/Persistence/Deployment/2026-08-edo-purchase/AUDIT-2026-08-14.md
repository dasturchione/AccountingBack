# EDO → Purchase pre-deployment audit — 2026-08-14

## Release scope

- EDOCS and DIDOX historical inbox discovery.
- Mapping and conflict resolution.
- Draft Purchase creation only.
- Contract/provider identity mapping.
- Durable bulk import and background organization scope.
- No posting, payment, balance, warehouse movement or provider mutation is part of this release.

## Verified safety controls

- Organization scoping is applied to HTTP and background execution.
- Candidate import is transactional and idempotent.
- Import-plan, mapping-plan and conflict hashes protect against stale operator decisions.
- Provider-document and marking locks protect concurrent imports.
- Imported Purchases are created only as Draft.
- Raw marking values and raw DIDOX status payloads are not returned or logged.
- EDOCS and DIDOX provider adapters remain isolated behind the EDO abstractions.
- Application and Domain projects do not depend on Infrastructure or Presentation.

## Architecture decision

The global 207-table repair is not an EDO-only mechanical change. It requires a separate FA/RTL migration and application refactor with module-specific tests. Adding empty entities or copying a scaffold would make counts look equal while risking invalid runtime SQL and broken FA APIs.

For the EDO deployment, use a scoped release commit and exclude unrelated AI, notification, local configuration, token-cache and backup changes. Treat the global FA/RTL parity repair as a separate release unless it is explicitly chosen as a deployment blocker.

## Go / no-go gates

### EDO scoped release

Go only when all conditions are true:

1. Recoverable database backup is verified.
2. `preflight.sql` passes.
3. `0148_unify_document_number_generation.sql` is applied to the exact target database.
4. `postflight.sql` passes.
5. Release build and all tests pass from the curated release tree.
6. Staged diff contains no local secrets, token caches, backups or unrelated modules.
7. No bulk import is running during deployment.

### Strict global 207 parity release

No-go until the missing FA/RTL migration history is reconstructed, generated and Domain models are reconciled exactly, affected FA services are migrated, and regression tests pass.
